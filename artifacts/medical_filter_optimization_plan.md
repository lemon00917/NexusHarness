# AI病历智能筛选优化计划

## 2026-07-12 正式执行版

### 1. 建设目标

将当前病历筛选能力收敛为一套元数据驱动、支持多维问题、证据可追溯的智能执行链：

```text
用户自然语言
→ 多维条件理解
→ 标准查询 IR
→ 动态 EvidencePlan
→ 多来源数据获取
→ 统一 EvidenceItem
→ 确定性规则判断
→ 三态证据聚合
→ 结构化结论
→ 用户解释
```

“智能”不是增加更多关键词分支，也不是让 LLM 直接决定患者是否符合，而是能够动态识别并组合以下维度：

- 人口学：年龄、性别等。
- 就诊：住院时间、住院天数、科室、就诊次数等。
- 诊断与疾病：当前诊断、入院诊断、出院诊断、既往史、疑似和排除诊断。
- 症状与体征：部位、程度、持续时间、频率和否定语境。
- 用药：开立、执行、实际给药、停药、剂量、频次和途径。
- 检验：阈值、参考范围、异常标志、趋势、次数和极值。
- 手术与操作：事件名称、时间、次数和术前术后关系。
- 文档语义：诊断依据、入院情况、治疗经过、出院情况等章节角色。
- 时间与事件：住院期间、术前、术后、首次、最近一次和连续时间段。
- 逻辑与量词：AND、OR、NOT、至少一次、全部、任意一次和持续。

### 2. 核心约束

1. 不针对具体疾病、药品、检验项目、文档名称或章节名称写判断分支。
2. LLM 负责理解、实体归一、候选证据规划和解释；程序负责患者隔离、数据获取、时间计算、数值比较和逻辑聚合。
3. 文档和章节通过 `document_role`、`section_role`、`evidence_types`、`purpose`、`aliases` 等元数据选择。
4. 关键词和字符覆盖只用于候选召回，不能直接改变最终结论。
5. 未取得数据、接口失败、缺少时间锚点和单位不兼容不能等同于不符合。
6. 每个结论必须能够追溯到具体记录、字段、文档章节、时间、数值和判断规则。
7. 保留现有 API 地址、请求参数和主要返回字段；新能力采用新增字段和兼容适配逐步切换。
8. 每个阶段独立提交、独立测试、独立验收，不一次性重写主流程。

#### 架构职责边界

```text
LLM：查询理解、实体归一、候选来源规划、规则无法覆盖的语义消歧、事实约束下的解释
程序：患者隔离、数据访问、时间与数值计算、单位换算、三态聚合、证据校验和结果审计
```

- LLM 不直接替代确定性事实，不得把 `UNKNOWN` 改成符合或不符合。
- 程序不得针对具体疾病、药品、检验项目、文档名、章节名、服务 ID 或院方编码写业务判断。
- 文档和结构化来源通过元数据能力、证据角色、适用场景和优先级扩展。
- 内部病历元数据发生变更时必须明确列出差异，保证外部实时元数据接口同步更新。

#### P0 金标准评测验收标准

1. 同一案例可选择调用实时 `/api/medical/query`，也可对保存的响应进行离线回放评分。
2. 每项断言独立可选；只有已人工确认的医学结论才填写预期结论，其他案例只校验拆分、路由和证据链，不猜测患者结论。
3. 基础设施失败与医学判断错误分开统计；接口不可用、上游超时不算临床假阴性。
4. 数据、时间锚点、单位或关键事实不足导致的 `无法判断` 单独统计，不强行计为不符合。
5. 至少输出：总体状态准确率、子条件准确率、路由断言通过率、证据断言通过率、无法判断率、基础设施失败数、平均/P50/P95 耗时和逐案例失败明细。
6. 后续 P1～P7 每次改造前后使用同一版本案例集对比；出现已确认案例回归时不得进入下一阶段。
7. 金标准变更必须经过人工复核并记录原因，不能为了让当前实现通过而修改预期结果。

#### 首批案例覆盖范围

- 复合条件：年龄、症状、住院时间窗、检验异常。
- 用药与检验组合：术前用药、定性异常、数值阈值。
- 就诊与症状组合：住院天数、背痛或烧伤。
- 出院事件窗：出院后若干天内检验结果。
- 证据降级：结构化服务不可用但文档存在有效证据时，不能用失败来源覆盖有效证据。
- 严格三态：缺少数据、锚点、单位或必要字段时返回 `无法判断`。

- 已覆盖患者本人肯定陈述、明确否认、已排除、家属等非患者主体、疑似/考虑/待排、不除外、既往/历史语境以及既往后已缓解或消失等语义。

#### 2026-07-15 P1 第二批：诊断确定性判断

- 新增 `microharness/medical/diagnosis_rules.py`，只对结构化诊断来源且能明确对应目标实体的候选记录执行确定性判断。

- 本批规则按通用字段角色和语义状态工作，不包含具体疾病、文档名、章节名、服务 ID、院方状态编码或项目编码分支。

#### 2026-07-15 P1 第三批：文档时间语境绑定

- 文档局部语义判断新增可选 `TimeWindow` 和文档记录时间输入；无时间条件时保持原判断路径，不改变已有无时间条件行为。
- 时间约束只接受可核验依据：实体局部句段中的绝对日期、与查询同锚点的明确相对时间表达，或绑定中已存在且字段标签明确的记录日期时间。
- 绝对日期或记录时间位于目标时间窗内才允许文档阳性证据成为 `MATCHED`；明确在窗外返回 `NOT_MATCHED/DOCUMENT_TIME_OUTSIDE_WINDOW`。
- 查询要求时间窗但缺少事件锚点、实体局部时间或明确记录时间时返回 `UNKNOWN/DOCUMENT_MENTION_TIME_UNKNOWN`，不让 LLM 根据文档类型或章节位置猜测发生时间。

- 同一句中较早否认与后续明确时间事件的肯定陈述会按时间转折截断否定作用域，避免前一次否认覆盖后一次阳性。
- 本批没有自动追加数据库查询字段，没有修改内部/外部病历元数据、外部接口配置和现有 API 契约；外部病历元数据接口无需同步修改。

#### 2026-07-16 P1 第四批：有界跨句指代与上下文继承

- 文档语义判断按章节、段落和句子分段，支持在同章节、同段落、有限句距内解析“该症状”“上述疾病”“该情况”“其”等通用指代表达。

### 4. 阶段验收标准

#### 阶段 0：基线与患者隔离

- 任何病历数据库查询必须至少携带一组有效患者或就诊身份。
- 严格查询为 0 行时，兜底查询不得移除全部患者条件。
- 只传全局患者 ID、只传挂号/就诊号以及同时传两组身份均有测试覆盖。
- 固化当前核心问题的条件拆分、路由、证据和结论基线。

#### 阶段 1：多维查询 IR

- 每个原子条件能够表达领域、实体、属性、比较、时间、事件、状态、次数、否定和逻辑关系。
- “术前 24 小时使用过阿司匹林”能够表达手术事件依赖和用药状态，不退化为关键词列表。
- IR 校验失败时结构化重试或返回歧义，不允许执行层猜测缺失语义。

#### 阶段 2：动态 EvidencePlan

- 一个条件可以规划多个合理证据来源，而不是只选择一个文档或接口。
- “烧伤患者”能够根据元数据规划结构化诊断及具备诊断证据角色的文档章节。
- 外部新增文档或章节时，原则上只更新元数据，不修改 Python 疾病分支。
- 未知文档先进行名称、别名、角色和 purpose 映射，无法映射时保留路由诊断。

#### 阶段 3：统一证据模型

- 用药、检验、诊断、患者信息和文档片段统一输出 `EvidenceItem`。
- 证据包含来源、记录 ID、实体、时间、数值、单位、原文和原因码。
- 用户解释不再依赖各数据源自行拼接不可解析的长字符串。

#### 阶段 4：确定性执行器

- 时间窗、多事件选择、检验单位、异常标志、医嘱状态、否定和诊断确定性均由通用规则执行。
- 规则按条件类型和证据类型扩展，不按具体医学实体扩展。

#### 阶段 5：证据融合与三态聚合

- 原生支持 `MATCHED`、`NOT_MATCHED`、`UNKNOWN`。
- AND、OR、NOT 使用三值真值表。
- 多来源冲突按照可配置证据等级处理，并展示冲突来源。

#### 阶段 6：用户解释

- 逐条件展示查询来源、候选数量、具体记录、时间窗、数值比较和不符合原因。
- LLM 仅润色文字，不能修改结构化状态、原因码、时间、数值、单位和记录 ID。
- 润色失败或发生事实漂移时自动回退确定性解释。

#### 阶段 7：评估与保障

- 建立人工标注的多维黄金案例集。
- 统计条件拆分准确率、路由召回率、证据命中率、判断准确率、错误符合率、错误不符合率和 UNKNOWN 合理率。
- 新旧执行链先影子对比，再按配置灰度切换。

## 历史计划与改造记录

以下内容保留此前已经完成的设计、修复和验证记录，后续执行以上述“2026-07-12 正式执行版”为准。

## 目标

把当前能力从“LLM理解 + 局部补丁”收敛为可落地的四层架构：

1. Normalize 层：只做通用语言/符号/数字/单位归一化。
2. LLM Understand 层：只产出候选 IR，不直接决定最终判定。
3. Scope Guard 层：判断问题是否属于病历筛选能力范围，不相关时给出明确提示。
4. Deterministic IR Validator 层：校验原句语义约束是否被完整保留。
5. Executor 层：结构化查接口、算时间窗、比数值、聚合证据。

核心原则：业务实体不写死在代码里；药品、检验、诊断、字段、服务路由尽量来自 skill metadata、service catalog、medical catalog 或可维护配置。

## 当前盘点结论

### 2026-07-08 追加盘点

本轮围绕“严格判定、证据链完整、避免写死”补充了以下结论，后续继续按 metadata/IR/Executor 分层收敛。

#### 本轮已处理

- 用户解释层改为证据驱动：
  - 用药、检验、诊断、文档章节候选记录都尽量展示关键字段。

- LLM 路由异常不再静默丢弃：
  - LLM 返回未知文档/章节时，保留 `llm_invalid_targets`、`route_warnings`、`route_repairs`、`raw_response`。
  - 真实无效文档不用于查库，但必须进入证据链诊断，避免“为什么没查到”不可追溯。
- API 异常兜底：
  - `/api/medical/query` 对未捕获异常返回“无法判断/不可判定”，不直接 500 给前端。
  - debug trace 仅在 `MEDICAL_QUERY_DEBUG=1` 时返回。
- 复合条件拆分修复：
  - `40岁以上并且背痛，住院期间血红蛋白指标异常` 可稳定拆为 3 个 AND 子条件。
- 检验规则修复：
  - `术前48小时内中性粒细胞数偏低` 中的 `48小时内` 不再被误当作检验阈值。
  - `术前48小时内中性粒细胞数>1.5x10^9/L` 仍能保留真正数值阈值。
  - 参考范围 `2-7.7` 不再被解析成 `2` 和 `-7.7`。
  - 检验解释补充项目、检测时间、结果、单位、异常标志、参考范围、判断结论。
- Step1 展示修复：
  - `术前48小时内中性粒细胞数偏低` 的结构摘要不再显示成 `判断=≤48小时`，而是 `限定=术前48小时内`、`判断=偏低`。
- 裸疾病/症状路由修复：
  - `烧伤` 这类裸疾病/症状词，不应因文档目录未直接命中而提前放弃服务匹配。
  - 服务匹配到 `diagnosis-query` 时，路由继续返回结构化诊断服务。
- 病历章节证据改为 metadata 驱动：
  - 在 `configs/medical_catalog.json` 章节上增加 `evidence_roles`。
  - 疾病/症状存在类查询通过 `evidence_roles` 找候选章节，而不是在代码里写“烧伤查入院记录”。
  - 当前角色包括 `disease_symptom_evidence`、`diagnosis_evidence`、`symptom_evidence`。
- 文档到章节映射保留：
  - Executor 构建 DB 查询时保留 `targets` 映射，避免把所有章节拍平成全局列表后套给每个文档。
  - 例如出院记录只查自己的 `入院情况/入院诊断/出院诊断`，不再混入入院记录的 `主诉/现病史`。
- 配置加载兼容：
  - `medical_catalog.json` 用 `utf-8-sig` 读取，避免 Windows 工具写入 BOM 后目录加载失败。

#### 本轮暴露、下次需要继续优化

- `evidence_roles` 需要升级为正式元数据协议：
  - 当前是字符串数组，下一步建议改为对象数组，包含 `role/scope/priority`。
  - 示例：
    ```json
    {
      "role": "diagnosis_evidence",
      "scope": ["general", "discharge", "inpatient"],
      "priority": "primary"
    }
    ```
- 角色建议收敛为：
  - `diagnosis_evidence`：明确诊断结论，如入院诊断、出院诊断、初步诊断。
  - `symptom_evidence`：症状/主诉/发病经过，如主诉、现病史、入院情况。
  - `history_evidence`：既往病史/长期存在，如既往史。
  - `course_evidence`：住院期间病情变化或补充发现，如诊疗经过、住院病程。
  - `procedure_evidence`：手术/操作证据，如手术名称、手术经过。
  - `anchor_evidence`：时间锚点，如入院日期、出院日期、手术日期。
- 场景建议：
  - `general`：无明确时间锚点的“XX患者/存在XX”。
  - `admission`：入院时、入院前、入院诊断。
  - `discharge`：出院诊断、最终诊断、出院时。
  - `inpatient`：住院期间、本次住院、住院过程中发现。
  - `preop/postop`：术前/术后。
  - `outpatient`：门诊/急诊。
- 优先级建议：
  - `primary`：可直接支持结论，如结构化诊断、诊断章节。
  - `supporting`：辅助证据，如主诉、现病史、入院情况。
  - `context`：上下文证据，不单独判符合。
  - `anchor`：只做时间锚点。
- 疾病/症状类路由需要按 `role + scope + priority` 选证据：
  - `诊断类查询`：优先 `diagnosis_evidence + primary`。

### 2026-07-27 症状语义关系二次复核

### 2026-07-27 多候选语义召回与确定性聚合

自由文本语义召回由每篇文档最多一个候选扩展为最多五个候选，避免原文先否定后肯定、当前与既往并存或多个相关表达时只审核第一处。模型只按原文顺序提取 `matched_entity` 和 `evidence_span`，程序逐项完成原文子串校验、临床蕴含审核、症状同一性复核以及主体、否定、确定性和时间判断。

最终四态由程序聚合，不由模型投票：存在有效阳性证据时为 `MATCHED`；完整检查后存在明确否定或约束失败时为 `NOT_MATCHED`；完整检查且没有目标实体时为 `NOT_MENTIONED`；候选格式无效、搜索不完整、超过候选上限或语义关系不确定时为 `UNKNOWN`。阳性证据已经完成审核时，可在同批其他候选不确定的情况下保留阳性结论，并在证据 trace 中记录全部候选状态。
